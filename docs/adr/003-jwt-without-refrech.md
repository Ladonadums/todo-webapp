# 003. Использовать JWT без refresh-токенов в MVP

## Контекст
Нужно реализовать аутентификацию. Варианты: JWT с access + refresh токенами или только access-токен.

## Варианты
- **JWT + refresh**: более безопасно, позволяет продлевать сессию без повторного ввода пароля.
- **Только access-токен**: проще реализовать, меньше компонентов.

## Решение
В MVP используется **только access-токен** (TTL = 15 минут), потому что:
- Цель — продемонстрировать архитектуру, а не full-featured auth,
- Refresh-токены требуют хранилища (Redis) и усложняют логику,
- Для учебного проекта это избыточно.

## Последствия
- Пользователь должен логиниться чаще,
- В будущем можно легко добавить refresh-токены.
