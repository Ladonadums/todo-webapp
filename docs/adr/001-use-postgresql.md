# 001. Использовать PostgreSQL вместо SQLite

## Контекст
Необходимо выбрать СУБД для хранения данных пользователей и задач. Возможные варианты: SQLite (встроенный), PostgreSQL (клиент-сервер).

## Варианты
- **SQLite**: простой, не требует отдельного сервера, но не поддерживает конкурентный доступ из нескольких процессов.
- **PostgreSQL**: полноценная реляционная СУБД с поддержкой транзакций, типов, миграций и одновременных подключений.

## Решение
Выбран **PostgreSQL**, потому что:
- Проект использует микросервисную архитектуру — несколько сервисов могут обращаться к БД.
- Требуется надёжность и соответствие production-стандартам.
- Легко развёртывается через Docker Compose.

## Последствия
- Увеличение сложности локальной разработки (но компенсируется Docker),
- Готовность к масштабированию и production-развёртыванию.
